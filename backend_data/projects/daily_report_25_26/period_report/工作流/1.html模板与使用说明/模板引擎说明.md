# 大连洁净能源集团通用经营分析与专项汇报 HTML 演示引擎：数据层级架构与 AI Agent 接口开发规范

本规范文档旨在定义一套高信息密度、强逻辑叙事、适配 16:9 宽屏投影与桌面审阅的 **HTML 交互式分析汇报引擎标准**。后续任何 AI Agent 在接收到用户的**《基础源数据》**与**《汇报撰写需求说明》**后，必须严格遵循本规范与配套的 `模版引擎.html` 演示母版，生成单文件自包含（Single-File Self-Contained）的 HTML 汇报页面。

## 第一部分：通用数据层级展示逻辑架构规范（L1–L4 金字塔叙事模型）

无论是年度/季度经营计划、财务预算执行分析、生产运营复盘、销售业绩归因还是专项课题汇报，优秀的分析汇报材料均遵循 **“L1 决策总览 → L2 全口径底座 → L3 业务维度深潜 → L4 效益归因与专项管控”** 的四层金字塔逻辑架构（即 **“总 — 纲 — 维 — 效”** 模型）：

| 层级编码 | 层级名称 | 核心叙事目标 | 标准承载版式 | 数据粒度与表达范式 |
| :--- | :--- | :--- | :--- | :--- |
| **L1** | **决策总览层**<br/>(Executive Summary) | 30秒内向决策者传递“基本面是否稳健、最显著的结构性变化在哪里、最终效益结果如何” | **版式 A**（封面 Bento 总览页）<br/>**版式 B**（全量指标谱系与结构页） | **6大北极星KPI卡片**（含省市平台总投诉量与住建局考核净投诉量双卡，严禁相加）+ **期间每日平均气温与同期对比曲线图（仅展示本期与同期日均气温双线对比）** + **5大结构化定性要点卡片** + **核心指标同比红增绿减排序柱状图** |
| **L2** | **全口径底座层**<br/>(Master Data Matrix) | 100%忠实呈现全集团/全盘核心指标汇总表，提供可随时查阅、交叉核对的“单一事实来源” | **版式 C**（双栏全量汇总大表页） | **20~30项指标左右双栏等高拆分** + **顶部分类高亮筛选器**（产销规模类 / 资源投入类 / 过程能耗类 / 效率与成本类） |
| **L3** | **业务维度深潜层**<br/>(Dimensional Deep-Dive) | 按业务逻辑链条（如：前置外部假设 → 核心产出 → 细分业务 → 组织分配 → 资源单耗）逐一剖析“为什么变、谁在贡献” | **版式 D1**（左文表+右瀑布/对比图）<br/>**版式 D2**（左文表+右均值红线对标图） | **“总量净变 → 各子单元增量贡献瀑布图”** + **“分月/分季时序排产曲线”** + **“同期○→本期●及全集团均值红线对标图”**（暴露高于均值 N 倍的异常单元） |
| **L4** | **效益归因与专项层**<br/>(Financial & Cost Control) | 将前端业务量与物耗变化转化为财务货币语言，拆解利润驱动因子，并对重点敏感费用进行横纵双维监控 | **版式 D2**（左文表+右双向归因图）<br/>**版式 E**（左文表+右2×2四图切换页） | **“可比口径下增收 vs 节支双轮驱动水平条形图”** + **“各单元收入贡献 vs 成本节支组合图”** + **“分单元横向对比 + 分月度纵向节奏四宫格切换”** |

### 层级复用与动态编排原则（非硬性目录大纲声明）

> [!IMPORTANT]
> **L1–L4 是分析汇报的【认知深度与版式选型工具箱】，而非硬性固定的目录大纲与强制章节序列。**
> 
> 在具体的自动化生成任务中，AI Agent 必须遵循以下动态编排契约：
> 1. **大纲结构以当期需求为绝对准绳**：最终汇报材料的具体章节名称、总页数及先后顺序，**100% 以用户的《当期汇报撰写需求说明》为准**，严禁机械僵化地按 L1/L2/L3/L4 强行凑齐四大部分。
> 2. **版式自由选配与多页深潜**：AI Agent 应当根据各章节的业务表达重点，自由挑选与组合最契合的版式（例如：一份 4 页的极简生产周报，可直接由 1 页 L1 版式 A + 3 页 L3 版式 D 组成，无需配置 L2 全量表与 L4 财务归因；而大范围专项复盘亦可连续排布多页 L3 维度深潜）。
> 3. **业务题材通用性泛化适配**：对于不涉及财务利润/费用的纯生产调度、工程施工协同（如保温管供货与安装）、设备检修或安全运行专项，L4 层级应直接泛化为“工程阻滞归因”、“技术工艺对标”或“工况异常专项诊断”，绝不强制包含货币效益测算。

### 数据叙事的“黄金五律”（AI Agent 撰写正文与设计图表必遵）

1. **结论先行（Assertion-Evidence）**：每个段落（`.reading-para`）首句必须用 `<strong>` 给出明确的定性判断（如：`<strong>1. 总量稳步扩张，各业务单元贡献分化。</strong>`），严禁无结论的流水账罗列。
2. **三元完整度量（数值 + 绝对增减 + 同比/占比）**：正文中提及关键指标时，尽量同时给出 `本期数值（同比增减量，同比变化率%）` 或 `占总量比重%`，并使用语义化色彩标签包裹。
3. **总额与结构拆解联动**：凡是总量发生变动（或总量看似持平但内部剧烈分化），必须往下拆解一层：
   - **空间/组织拆解**：拆解到各事业部、区域、工厂、门店的增量贡献（配瀑布图或分组柱状图）；
   - **时间节奏拆解**：拆解到各月/各季度的波峰波谷移位（配柱线组合趋势图）；
   - **物理/业务结构拆解**：拆解到一级/二级/三级子科目（如总耗水拆解为源头耗水、干线补水、终端补水，明确指出“XX%的减量来自某一级子项”）。
4. **相对降幅与绝对基数双维对标**：分析单耗、损耗率、转化率、费用率时，绝不能只报“同比下降 X%”，必须同步对比**各单元绝对值与全局均值基准线（红虚线）的倍数关系**（例如：“尽管 D 单元单耗同比下降 27.9%，但其绝对值 90.0 仍为全集团均值 45.3 的 1.99 倍”）。
5. **可比口径经营归因**：在进行财务利润或成本效益分析时，明确说明测算基准（如剔除外部大宗价格波动的可比单价、内部关联交易抵销规则），将净效益增量拆解为 **“前端业务增收贡献（%）”** 与 **“后端成本节支贡献（%）”** 两大驱动轮。

## 第二部分：五大标准页面版式规范与空间预算（Slide Archetypes A–E）

模板引擎采用 16:9 宽屏视口固定高度设计（`.slides-viewport { height: calc(100vh - 92px); }`）。为确保每一页在标准分屏下**既不出现大片空白，也不发生局部挤压截断**，AI Agent 必须根据该章节的内容形态选择以下 5 种标准版式之一：

| 版式代号 | 版式名称 | `.slide-body` 类名 | 左栏构成 (`.script-panel`) | 右栏构成 (`.visual-panel`) | 单页容量预算上限 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **版式 A** | **L1 封面与高管摘要全屏页** | `slide-body single-col bg-slate-100/90 !p-4` | 无左右分栏（全屏上下结构）：<br/>• 顶部左5右7渐变横幅（主标题+总纲引言 + 6张核心KPI卡片）<br/>• 底部 6列栅格（5张结构化要点 Bento 卡片，上3张各占2列，下2张占4列+2列） | 同左（全屏一页） | 顶部固定 6 张 KPI 卡；底部固定 5 张（或 6 张）要点卡，每卡正文 80～140 字 |
| **版式 B** | **L1 全局谱系与结构拆解页** | `slide-body` | 纯念稿模式（无附表）：<br/>• 放置 4～6 个 `.reading-para` 导读段落，完整展示第一章总体情况正文 | 上下复合布局：<br/>• 上图（占高52%）：12～18项核心指标同比排序柱状图<br/>• 下图（占高48%，`grid-cols-2`）：2幅并列的三级结构对比柱状图 | 左栏 4～6 段文字；右栏 1 大图 + 2 并列小图 |
| **版式 C** | **L2 全口径双栏汇总矩阵页** | `slide-body single-col` | 无左右分栏（全屏上下结构）：<br/>• 顶部 1 个 `.reading-para`（内嵌 `[data-table-filter]` 分类筛选按钮组）<br/>• 下方 `grid-cols-1 lg:grid-cols-2` 左右并排两张 `.data-table-wrap` | 同左（全屏双栏表） | 每栏表格 8～14 行（两栏合计 16～28 项指标），一屏完整显示无需纵向滚动 |
| **版式 D** | **L3/L4 标准图文表分屏页**<br/>*(主力版式，占全篇70%以上)* | `slide-body` | 上文下表结构：<br/>• 工具栏含 `.expand-table-btn` 放大按钮<br/>• 上方 1～3 个 `.reading-para` 分析段落<br/>• 下方 1 张首列冻结的 `.report-table`（建议 5～10 行） | 灵活图表组合（三选一）：<br/>• **D-双图上下叠放**：2个 `.chart-card` 纵向均分（最常用）<br/>• **D-一主二副**：1个主图 + 底部2个并列副图或3张指标说明卡<br/>• **D-三联横向对标**：`grid-cols-3` 并排3幅水平单耗对标图 | 左栏 1～3 段文字 + 1 张 5～10 行附表；右栏 2～3 幅 ECharts 图表 |
| **版式 E** | **L4 四宫格多维视图切换页** | `slide-body` | 上文下表结构（同版式 D） | 四图切换面板（`[data-view-switch-container]`）：<br/>• 顶部视图切换条（四图同屏 / 分单元横向对比 / 分月度纵向节奏）<br/>• 下方 `.view-switch-grid` 容纳 4 个带 `data-chart-group` 的 `.chart-card` | 左栏 2 段文字 + 1 张附表；右栏 4 幅 ECharts 图表（2×2 网格） |

## 第三部分：HTML 模板引擎 DOM 契约与 CSS 组件接口字典

AI Agent 在基于 `模版引擎.html` 生成新页面时，**严禁修改 `<style>` 样式表与 `<script>` 前半部分的内核逻辑**，只需替换以下 3 处插槽：

1. **全局标题插槽**：
   - `<title>` 标签文本
   - `#drawerReportTitle`（侧边目录抽屉标题）
   - `#topBarReportTitle`（顶部控制栏主标题）
2. **主视口幻灯片容器（`<main id="slidesViewport">`）**：在其中按顺序排布 `<section class="slide-page">`。
3. **图表注册表插槽（`const CHART_REGISTRY = { ... }`）**：按页码索引（0-based）注册每页的 ECharts 渲染函数。

### 3.2 念稿段落与语义化数字标签契约（红增绿减契约 `.reading-para` & `.num-*`）

左侧 `.script-scroll` 内的每个自然段必须包裹在 `<div class="reading-para">` 中（每页的第 1 个段落默认加上 `reading-active` 类）。正文与附表中的差异率及增减数值必须严格遵循**“红增绿减”**行业惯例（增加为红色，减少为绿色）：

| CSS 类名 | 视觉效果 | 适用业务语义场景 | HTML 写法示例 |
| :--- | :--- | :--- | :--- |
| `.num-pos`<br/>`.num-up` | **浅红底深暗红粗体**<br/>(`text-red-700 bg-red-50`) | **增加为红色**：适用于正向业务增长、同比增加、差异率为正、利润增加等 | `<span class="num-pos">+4.20%</span>`<br/>`<span class="num-up">+58.5万吨</span>` |
| `.num-down`<br/>`.num-dec` | **浅绿底深青绿粗体**<br/>(`text-emerald-700 bg-emerald-50`) | **减少为绿色**：适用于能耗/物耗同比下降、单耗压降、成本节支、差异率为负等 | `<span class="num-down">-14.25%</span>`<br/>`<span class="num-dec">-9.5万GJ</span>` |
| `.num-warn` | **浅黄底深琥珀粗体**<br/>(`text-amber-800 bg-amber-50`) | **预警高亮**：单耗高于集团均值预警、工况突变、极端低温异常等 | `<span class="num-warn">90.00 kg/㎡（均值1.99倍）</span>` |

> ⚠️ **红线防错**：严禁将增加标为绿色或把减少标为红色！无论正文差异率文字、表格单元格还是统计图表柱体/曲线，必须统一执行**增加为红色、减少为绿色**。

### 3.3 首列冻结数据表与一键宽屏放大契约 (`.report-table` & `.expand-table-btn`)

凡是在分屏页左栏包含数据表，必须在 `.panel-toolbar` 放置 `.expand-table-btn` 按钮，并在 `.script-scroll` 下方放置 `.data-table-wrap`。**模板引擎会在页面加载时自动读取该表格并生成右侧宽屏大字放大层，无需手写放大层 HTML！**

```html
<!-- 1. 左侧工具栏放入放大按钮 -->
<div class="panel-toolbar">
  <span class="text-xs font-bold text-slate-700">📄 说明正文 & 表3-2（表名简述）</span>
  <button type="button" class="expand-table-btn px-2.5 py-1 rounded bg-sky-800 hover:bg-sky-700 text-white text-xs font-semibold transition">🔍 右侧宽屏放大表3-2</button>
</div>

<!-- 2. 在 .script-scroll 底部放入表格头栏与表格容器 -->
<div class="table-header-bar">
  <span class="text-xs font-bold text-slate-800">表3-2 完整表名（将自动作为右侧放大层标题）</span>
  <span class="text-[11px] text-slate-500">首列已锁定 · 支持右侧大屏展开</span>
</div>
<div class="data-table-wrap">
  <table class="report-table">
    <thead>
      <tr><th>单位/口径</th><th>本期计划<br/>(单位)</th><th>同期完成<br/>(单位)</th><th>同比增减</th><th>同比变化率</th></tr>
    </thead>
    <tbody>
      <!-- 汇总行或重点警示行加上 class="row-total" 呈现琥珀金底色高亮 -->
      <tr class="row-total"><td>集团汇总</td><td>1,395.5</td><td>1,392.3</td><td>+3.23</td><td>+0.23%</td></tr>
      <tr><td>主城区汇总</td><td>951.4</td><td>939.9</td><td class="text-sky-800 font-bold">+11.55</td><td class="text-sky-800 font-bold">+1.23%</td></tr>
      <!-- 子级缩进统一使用全角空格 "　" -->
      <tr><td>　北海汇总</td><td>593.7</td><td>584.9</td><td>+8.79</td><td>+1.50%</td></tr>
    </tbody>
  </table>
</div>
```

**表格排版铁律**：
- 表头 `<th>` 文字若超过 4 个汉字，必须使用 `<br/>` 折成两行（如 `计划供热<br/>(万GJ)`），严禁单行过宽撑爆表格导致出现长距离横向滚动条。
- 表格首列 `th:first-child` 和 `td:first-child` 已由 CSS 自动设为 `sticky` 冻结；层级从属关系使用全角空格 `　` 缩进。
- 表格内重点正向变化单元格可加 `class="text-sky-800 font-bold"`，重点压降/节支加 `class="text-teal-700 font-bold"`，重点超支/预警加 `class="text-red-700 font-bold"`。

### 3.4 通用插件协议：分类筛选 (`[data-table-filter]`) 与四图切换 (`[data-view-switch]`)

引擎已将两大高级交互封装为声明式 `data-*` 属性协议，可在任意页面零代码启用：

1. **表格分类高亮筛选协议**（常用于版式 C 全口径汇总大表）：
   - 在按钮容器上添加 `data-table-filter`，每个按钮添加 `data-filter-cat="all"` 或具体分类名（如 `data-filter-cat="prod"`）。
   - 在当前页 `tbody tr` 上添加对应的 `data-cat="prod"`。点击按钮时，非匹配行自动降为 `0.28` 透明度，匹配行高亮。
2. **四宫格图表放大切换协议**（常用于版式 E）：
   - 在右侧 `.visual-panel` 添加 `data-view-switch-container`。
   - 切换按钮组容器添加 `data-view-switch`，按钮分别设置 `data-view-mode="all"`、`data-view-mode="unit"`、`data-view-mode="month"`。
   - 下方图表网格容器保留 `.view-switch-grid` 类，内部每个 `.chart-card` 添加 `data-chart-group="unit"` 或 `data-chart-group="month"`。引擎自动完成网格列数切换与 ECharts `resize()`。

## 第四部分：ECharts 图表注册接口与 8 大标准分析图谱规范

### 4.1 懒加载注册机制 (`CHART_REGISTRY`)

由于非激活页（`.slide-page` 未处于 `.active` 状态）在切换过渡或隐藏时容器尺寸可能受影响，所有图表必须按所属页面的 `data-slide-index`（从 0 开始）注册在 `CHART_REGISTRY` 对象中，由 `goToSlide(idx)` 在切页后延迟 60ms 调用并触发 `resizeAllCharts()`：

```javascript
const CHART_REGISTRY = {
  // key 为页面的 data-slide-index
  1: function() {
    const c1 = getOrCreateChart('chart_id_1');
    if (c1) {
      c1.setOption({ /* ECharts 标准配置项 */ });
    }
  },
  3: function() {
    // 第4页的图表初始化...
  }
};
```

### 4.2 视觉色彩与字体铁律（大屏投影高可读性标准）

1. **统一语义色板（严禁使用刺眼的纯红纯绿或杂乱彩虹色）**：

## 第六部分：8:3 异形巨幕大屏投影模式与反向预挤压规范（模式一）

### 6.1 业务背景与物理拉伸痛点
在集团指挥调度中心或会议室中，许多超宽拼接大屏（LED 屏或多联带鱼屏）物理比例为 **8:3**（$\text{宽高比} \approx 2.67:1$）。然而，主控电脑通过 HDMI/Type-C 投屏输出的通用视频信号往往是标准的 **16:9**（$1.78:1$）。
大屏视频处理器若采用强制铺满策略，会在**水平方向上强行拉伸 1.5 倍**（$\frac{8/3}{16/9} = 1.5$），导致常规 16:9 网页中的饼图被压成扁椭圆、正方形卡片变形、文字严重拉长发胖，严重破坏会议汇报的专业美感。

### 6.2 模式一：超宽 8:3 排版 + 反向预挤压（Anamorphic Squeeze）实现原理
为彻底解决大屏畸变，模板引擎实现了**“8:3 巨幕预压”**机制（模式一）：
1. **排版扩展**：激活 `body.screen-8-3` 后，主视口 `.slides-viewport` 宽度扩展至 **150%**，使页面内部的栅格卡片与图表在更从容开阔的 8:3 超宽视野中排版；
2. **反向预挤压**：通过 CSS `transform: scaleX(0.6666667)`（即 $2/3$ 水平压缩因子，$\frac{1}{1.5} = \frac{2}{3}$），将扩展后的 8:3 内容水平向左挤压回 100% 电脑视口内，不产生横向溢出滚动条；
3. **大屏无损还原**：电脑将压缩画面输出至 8:3 物理大屏时，大屏控制器的 1.5 倍物理硬件拉伸正好与网页内部的 $2/3$ 预压缩**两两完全抵消**（$1.5 \times \frac{2}{3} = 1.0$）；
4. **最终交付效果**：
   - 在大屏上，**所有圆形图表、正方形卡片和文字完全恢复为标准的 1:1 几何长宽比**，绝无变形；
   - **整块 8:3 巨幕无黑边满屏铺满**，视觉气势磅礴，彻底告别拉长发胖问题。

### 6.3 交互与使用规范
* **顶栏切换按钮**：顶栏显式提供 `📺 16:9` 与 `🖥️ 8:3 预压` 双态胶囊按钮，选定状态自动持久化于 `localStorage.getItem('report_screen_ratio')`；
* **键盘快捷键**：会场演示时，直接敲击键盘数字键 **`8`** 即可在 16:9 与 8:3 两种比例之间快速一键切换；
* **ECharts 联动重绘**：切换比例时，引擎内置的 `resizeAllCharts()` 会自动重新测量并计算 Canvas 物理尺寸，确保图表标签、坐标系与线条在 8:3 超宽布局下流畅重绘。
